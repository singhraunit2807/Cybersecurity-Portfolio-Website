Kernel-Level Runtime Protection — eBPF-AIMES

eBPF-AIMES is an AI-assisted Linux security architecture focused on kernel-level behavioral monitoring, anomaly detection, risk scoring and defensive response. The concept combines low-level eBPF telemetry with userspace AI/ML analysis so security decisions can be based on observed runtime behavior rather than only static rules.

Linux System Activity→eBPF Sensors→Event Collection→Feature Extraction→AI/ML Analysis→Risk Score→Decision→Response / Dashboard

Problem & Objective

Monitor process, file and network behavior at Linux kernel level, identify deviations from expected behavior, assign a risk score and support defensive actions such as allowing, alerting or blocking suspicious activity.

Kernel Telemetry

  • Process execution / execve
  • File access / openat
  • Network connection / connect
  • Process creation
  • File modification activity

Event Data

Structured telemetry can capture fields such as PID, process, action, destination, port and timestamp. These events form the behavioral data stream consumed by the analysis layer.

AI / ML Layer

Behavioral analysis can use supervised and anomaly-detection approaches such as Random Forest, XGBoost, Isolation Forest, Autoencoder and LSTM models, depending on the detection objective and available training data.

Risk Scoring

The design uses a 0–100 risk concept. A low score such as 0–30 represents normal behavior, while 31–60 is treated as a monitoring range. Higher-risk behavior can be escalated through the response layer according to configured policy.

Response Layer

Security decisions are mapped to defensive outcomes such as Allow, Alert or Block. The goal is to move from passive visibility toward automated, policy-driven runtime defense.

Technology Stack

Linux/Ubuntu, eBPF with BCC or libbpf, C/eBPF for kernel-side instrumentation, Python for userspace processing and AI/ML, with FastAPI/Streamlit for service and dashboard layers and SQLite/PostgreSQL for event storage.

Methodology

Establish behavioral baselines → collect kernel telemetry → normalize events → extract behavioral features → detect anomalies → calculate risk → apply policy → generate alert/response → visualize and audit events.
